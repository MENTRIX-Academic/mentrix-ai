# MENTRIX — Sprint 07: تحسين قراءة الخط اليدوي

**التاريخ:** 4 نوفمبر 2026 · **نوع التسليم:** تطوير برمجي + اختبارات هندسية، **وليس دراسة دقة OCR جديدة**.

## المشكلة في النسخة السابقة

- TrOCR (`microsoft/trocr-base-handwritten`) يتعامل مع **صورة سطر واحد**، لذلك فشل فصل السطور في الورقة الكاملة يُضعف جودة النتيجة حتى لو كان موديل التعرف نفسه جيدًا.
- التقسيم السابق اعتمد على عدد البكسلات الداكنة في كل صف (`Row Projection`) مع عتبة ثابتة؛ لا يتكيف جيدًا مع الضوء غير المنتظم أو الورق المسطر أو بعض صور الهاتف المائلة.
- كانت مراجعة أخطاء القراءة صعبة، وتحديد مناطق الأسئلة يتم بكتابة JSON يدويًا.
- أُصلح سابقًا خطأ إخفاء النص المستخرج عندما لا يتعرف النظام على علامات `Q1` و`Q2`، وتم الحفاظ على هذا الإصلاح.

## ما تغير فعلًا

| الجزء | التعديل | حالة الإثبات |
|---|---|---|
| فصل السطور | `handwriting_layout.py`: Adaptive Local Threshold + إزالة المساطر/الحدود الطويلة + Deskew محدود ±5.5° + Bounding Boxes أصلية | اختبارات صناعية بالصور؛ ليس قياس CER/WER بشري |
| التوافق | اختيار `smart` افتراضيًا، أو `legacy` للمقارنة، والرجوع للطريقة القديمة عند عدم توفر OpenCV | كود مختبر |
| السطر الواحد | حماية الـCrop المنفصل من الضياع عند عدم اكتشاف مناطق حبر؛ لا يجري تمرير الورقة الكاملة عشوائيًا إلى موديل السطور | كود مختبر |
| إعادة القراءة | `retry_unclear` اختياري: محاولة ثانية بسياق معالجة مختلفة عند النص الفارغ أو تكرار شاذ؛ بحد أقصى 12 محاولة إضافية في الورقة | سيناريوهات بموديل وهمي؛ لا يوجد دليل تحسن دقة |
| واجهة المعيدة | معاينة قصاصة الصورة الأصلية لكل سطر جنب توقع OCR، وعرض التحذيرات والبدائل | API مختبر؛ متصفح Windows الفعلي يحتاج تجربة |
| تحديد السؤال | سحب مستطيل حول إجابة أي سؤال من الصورة الأصلية، ثم تشغيل OCR مجددًا بالمناطق المختارة | API وتحويل الإحداثيات مختبران؛ سحب الماوس يحتاج تجربة بشرية بالمتصفح |
| الأمان | لا يتم تسجيل درجات أو نشرها بناءً على OCR فقط؛ يظل التأكيد البشري ضروريًا | اختبارات API |

**الفصل بين المراحل لم يتغير:** Original page → candidate line detection → TrOCR line recognition → question matching/TA-defined regions → independent human verification → conservative grading → batch publish.

## الملفات الرئيسية المعدلة والمضافة

- `research/sprint6/handwriting_layout.py` — معالجة الصفحة واكتشاف السطور والتصحيح المحدود للميل.
- `research/sprint6/full_sheet.py` — توجيه الصور للمكتشف الذكي والـFallback والمحاولة الثانية، وإرفاق بيانات كل سطر.
- `handwriting_routes.py` — تفعيل خيارات API، حفظ صور القصاصات للمعيدة، وعرض صفحات PDF كصور عند الحاجة.
- `static/handwriting_review.js` — معاينة النص بجانب قصاصات الأصل ورسم مناطق السؤال بالماوس.
- `static/workspace.js` و `static/index.html` — ربط الواجهة بالخيارات الجديدة.
- `research/sprint6/requirements_ocr.txt` — إضافة OpenCV حتى تعمل الميزة الذكية بعد تثبيت تبعيات OCR.
- `research/sprint6/tests/test_sprint07_handwriting.py` — اختبارات جديدة للميل والمسطرة والمسار من الـAPI إلى العرض والمراجعة.

## ما الذي أثبتته الاختبارات؟

أُجريت `python -m pytest -q` على جذر المشروع؛ **93 اختبارًا ناجحًا**، منها **8 اختبارات إضافية** تغطي صورًا صناعية بزاويا 0 و+2.5 و−3.5 و+5 درجات، صفحة فارغة، المقارنة مع Legacy، إعادة القراءة بموديل وهمي، ومراجعة الصور عبر API ثم إعادة التشغيل بمناطق مختارة. **كذلك اجتاز ملفا JavaScript فحص الصياغة بـ`node --check`.**

هذه الاختبارات تثبت سلوك البرمجيات على مدخلات محددة؛ **لا** تثبت دقة قراءة خط يد بشري. لا توجد في ملفات هذا التسليم مجموعة صور خط يد بشرية جديدة ذات Ground Truth مؤكد، ولا أوزان TrOCR مخزنة في بيئة التشغيل، لذلك لم يُنفّذ هنا استدلال فعلي بالموديل على هذه الصور ولم تُحسَب CER/WER جديدة.

## تجربة المعيدة على Windows

1. افتحي `START_MENTRIX_HERE.bat` و`INSTALL_SPRINT06_OCR.bat` من فولدر MENTRIX.
2. افتحي Quiz Grading ثم ارفعي JPG/PNG/PDF يضم إجابات بخط يد إنجليزي.
3. اختاري `Smart line detection` وبدايةً `E01_base_rgb`، واضغطي `Read handwriting with TrOCR`.
4. افتحي `Raw TrOCR output` ثم `Compare original handwriting with OCR` لتحديد السطور التي قُرئت خطأ.
5. لو الأسئلة لم تتطابق، افتحي `Mark question areas directly on image`، حددي Q1 واسحبي مربعًا حول الإجابة وكرري، ثم أعيدي OCR.
6. عند احتياج إعادة قراءة سطر فارغ، فعّلي `Extra pass` (أبطأ خصوصًا CPU). قارني النتيجتين ولا تعتمدي أيًّا منهما دون مراجعة.
7. قارني النص والصورة، أدخلي الإجابات المصححة، ثم `Verify & grade`، ثم مراجعة الدرجات والنشر الدفعي الآمن.

**ملاحظة:** لتطبيق المناطق الجديدة يجب إعادة الضغط على زر OCR؛ مجرد رسم المستطيلات لا يعيد قراءة الصفحة تلقائيًا. الصور المائلة بأكثر من نطاق التصحيح، الأسئلة ذات الأعمدة المتعددة، الصيغ الرياضية المعقدة، والخط الإنجليزي المتداخل جدًا قد تحتاج تحديدًا يدويًا أو موديل/كاشفًا أقوى. **الخط العربي ليس ضمن V1.**

## المطلوب لإثبات تحسن حقيقي

- تجميع صور خط يد إنجليزي حقيقية وموافقة استخدام مناسبة، بما فيها أوراق سكشن ممثلة للبيئة المقصودة، وتفريغ بشري مستقل لكل سطر وإجابة.
- مقارنة `smart` مقابل `legacy` على **نفس الأوراق** ثم قياس: Line Detection Recall, OCR CER/WER, سؤال→إجابة Mapping، زمن الـCPU، وحالات الالتباس.
- مقارنة E01–E04 على `Validation` ثم تقييم `Frozen Test` مرة واحدة كما هو موضح في وثائق Sprint06؛ لا نعلن موديل فائز قبل تنفيذ التجارب وتسجيل النتائج.
- لا يجوز اعتبار نجاح اختبارات الصفحة الصناعية أو موديل وهمي دليلًا على تحسين OCR حقيقي أو تجريب Fine-tuning.

**الخلاصة:** واجهة قراءة الخط اليدوي وفصل السطور أكثر عملية وقابلة للمراجعة، لكن التحسن الفعلي في دقة قراءة البشر ما زال **غير مقاس**.
